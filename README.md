# Planning — Le Comptoir (v2)

نسخه‌ی معماری جدید: Salle/Cuisine واقعاً جدا (نه رنگ ثابت روی آدم)، شناسه‌ی پایدار برای هر عضو،
اسناد جدا به‌ازای هر روز (رفع مشکل تداخل هم‌زمان چند مدیر)، بدون هیچ اسم تستی هاردکد‌شده.

## فایل‌ها
```
index.html   ← ساختار کامل اپ
style.css    ← طراحی (همون ظاهر قبلی + سوییچ Salle/Cuisine)
app.js       ← منطق کامل + Firebase
manifest.json, sw.js, icon-192.png, icon-512.png
firestore.rules.txt ← قوانین امنیتی جدید
```

## چیزی که عوض شد نسبت به نسخه‌ی قبلی

- **Salle/Cuisine** حالا یک سوییچ کلی بالای صفحه‌ست (نه یه ویژگی ثابت روی هر نفر). هرکسی می‌تونه
  یک روز در Salle و روز دیگه در Cuisine کار کنه — دپارتمان مال *سرویس*ه، نه مال *آدم*.
- هیچ اسمی (HAMID, MOMO, ...) دیگه توی کد نیست. اپ با یک تیم کاملاً خالی شروع میشه.
- هر عضو یک شناسه‌ی پایدار (memberId) داره، نه اسم — یعنی تغییر اسم دیگه هیچ‌وقت
  برنامه‌های قدیمی رو خراب نمی‌کنه.
- برنامه‌ی هر روز توی یک سند جدا ذخیره میشه (نه یک فایل بزرگ مشترک) — یعنی دو مدیر که
  همزمان روزهای مختلف رو ویرایش می‌کنن، دیگه تغییرات همدیگه رو پاک نمی‌کنن.
- فقط مدیرا می‌تونن عضو اضافه/حذف/تغییرنام بدن. کاربر عادی فقط از لیست موجود اسم خودشو انتخاب می‌کنه.
- عضو حذف‌شده واقعاً پاک نمیشه — فقط «غیرفعال» میشه، تا تاریخچه خراب نشه.
- هر سرویس سه حالت داره: «هنوز برنامه‌ریزی نشده» / «باز ولی کسی نیست» / «تعطیل» — با یه
  سوییچ Ouvert/Fermé توی همون پنجره.
- کپی به هفته‌ی بعد، فقط جاهای خالی رو پر می‌کنه، هیچ‌وقت روی برنامه‌ی موجود رو بی‌سؤال جایگزین نمی‌کنه.

## قدم‌های راه‌اندازی

### ۱. قوانین امنیتی Firestore رو آپدیت کن
`console.firebase.google.com` → پروژه‌ی `planning-equipe-44750` → Firestore Database → Rules
→ محتوای `firestore.rules.txt` رو کامل جایگزین کن → Publish

### ۲. فایل‌ها رو روی گیت‌هاب آپلود کن
دقیقاً مثل همیشه: `index.html`, `style.css`, `app.js`, `manifest.json`, `sw.js`,
`icon-192.png`, `icon-512.png` — جایگزین نسخه‌ی قبلی.

### ۳. نیازی به کار اضافه برای admins نیست
سند `planning/admins` که قبلاً تنظیم کردی (با uid های Hamid/Marla/Momo/Ugo) **دست‌نخورده
می‌مونه و کار می‌کنه** — همون uid ها همچنان مدیر شناخته میشن.

### ۴. اولین بار که باز می‌کنی
چون تیم از صفر شروع میشه، وقتی Hamid (که از قبل مدیر ثبت‌شده) اپ رو باز کنه، توی صفحه‌ی
Bienvenue یه فرم «افزودن به تیم» می‌بینه (چون مدیره) — از همونجا اسم خودش و بقیه رو اضافه
می‌کنه. بعدش برنامه‌ی هفته رو از تب «Semaine» دستی وارد می‌کنه (مثل قبل، با دایره‌های رنگی).

## نکته‌ی مهم درباره‌ی برچسب «Manager»

چون طبق تصمیم پروژه، اسم دیگه هیچ‌وقت برای امنیت استفاده نمیشه (فقط UID)، برچسب «Manager»
کنار اسم افراد یک نشونه‌ی *نمایشی* صرفه (وقتی خودشون یک‌بار با دستگاه مدیر وارد بشن، خودکار
ثبت میشه) — هیچ تأثیری روی دسترسی واقعی نداره.
